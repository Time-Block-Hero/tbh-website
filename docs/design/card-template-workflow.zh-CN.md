# TBH 卡牌模板的设计与制作建议

这是针对本项目的制作建议，不是 GPT‑6 Astra 固定使用的模板或已经批准的新卡面设计。本轮只调整编辑器工作区的美术风格，保留卡面、布局和玩法数据。

## 推荐的组合

**版式草图 → 美术资产 → 精确图层 → 浏览器实卡验收 → 游戏内验收。**

| 部分 | 推荐制作方式 | 原因 |
| --- | --- | --- |
| 卡框材质、浮雕、装饰边角 | 图像生成探索，精修后导出透明 PNG / WebP | 适合丰富的绘画与材质细节 |
| 箭头、属性图标、职业标记 | SVG 或矢量源文件 | 轮廓精确，方向、尺寸和不同状态保持一致 |
| 卡名、费用、攻击、生命、效果说明 | 动态文字图层 | 可随 JSON、语言和数值变化，不把文字烘焙进图片 |
| 裁切、位置、字号、层级、安全边距 | 布局 JSON + 渲染代码 | 同一套结构可批量显示所有卡牌 |
| 选中、悬停、禁用、拖拽反馈 | CSS / 运行时状态 | 属于交互表现，不需要为每个状态重新生成整张图 |

项目已经采用这个方向：`card_layout_ref/layout.json` 定义参考画布和图层；`card-editor.js` 的 `renderCard` 用图片与动态 DOM 文字按比例叠放，Canvas 用于文字测量等辅助操作。继续迭代现有机制即可，无需先改成一个全新的渲染引擎。

## 在哪里设计

- **Figma 等矢量版式工具：**适合人工比较卡框轮廓、字级、对齐、箭头位置和组件变体；能导出 PNG / SVG。它是可选的设计源，不必为了使用 Codex 强制增加一个维护环节。
- **图像生成与图像编辑工具：**适合探索有美术质感的边框、徽章、金属和织物装饰。最终资产仍需检查透明边缘、左右一致性、文字安全区和层之间的对齐。
- **当前浏览器编辑器：**最适合作为你和 Codex 反复审美、调参数的共同工作台。调整后立即用真实长卡名、长效果文本和不同插画检查。
- **Unity 实际对局：**最终检查卡牌在真实屏幕尺寸、桌面背景、移动和选中状态下能否读清。浏览器展示通过不能替代游戏内验收。

对你当前的工作方式，我建议优先用“浏览器工作台 + 图像生成 + 矢量图标”，有设计师加入时再把 Figma 源文件纳入交付。

## 建议先做一个小型卡面设计批次

1. 先确定信息层级与安全区：第一眼能读出卡名、费用、战斗数值与箭头，装饰服从阅读。
2. 准备 2–3 个明显不同的卡框方向，用同一张插画、同一组真实文字比较。
3. 选定方向后分别制作框、信息底板、费用徽章、属性徽章、方向箭头；固定参考画布、透明边界和导出尺寸。
4. 接入现有布局 JSON，至少检查随从、法术、长卡名、长效果、不同稀有度和多箭头组合。
5. 同时看 Hand View 和 Board View。桌面缩略卡需要的信息密度与大幅详情不同。
6. 确认后再扩展四职业与不同稀有度的变体；通过独立任务把正式资产送到 `tbh-assets`，保持 Unity GUID 和资源映射。

图像生成输出的是候选美术。箭头方向、数值、规则文字、稀有度和职业身份仍由结构化数据决定，不能依靠图片内容表达权威状态。

## 官方资料

- [GPT‑6 Astra 模型说明](https://developers.openai.com/api/docs/models/gpt-6-astra)：描述代码、工具与图像工具能力，没有规定卡牌游戏模板生产流程。
- [OpenAI 图像生成](https://developers.openai.com/api/docs/guides/image-generation)：支持透明背景 PNG / WebP，可用于可叠加候选资产。
- [Figma 导出格式](https://help.figma.com/hc/en-us/articles/13402894554519-Export-formats-and-settings-for-static-designs)：PNG、SVG 等格式的导出选择。
- [MDN SVG](https://developer.mozilla.org/en-US/docs/Web/SVG)：用于二维矢量图形的格式。
