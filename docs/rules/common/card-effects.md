**设计目录草案，待审阅。** 本章说明设计一项卡牌效果时需要描述什么，以及可以从哪些维度组织它。具体选择何时锁定、变化何时发生、触发何时处理，统一见[第八章：通用结算逻辑](effects.md)。目录中的候选选项不自动批准一种新玩法，也不表示编辑器已支持全部组合。

## 7.1 效果的工作方式

**DES-001 先确定工作方式，再描述结果。** 一张牌可以拥有多项独立效果；每项分别说明条件、对象与次数。关键词是这些规则的简写，状态是它们读取或留下的记录，定义见[2.4.1](elements.md#效果关键词与状态)。

### 7.1.1 主动能力

由玩家在允许的操作窗口主动声明发动。必要内容：来源可用区域、允许阶段、发动条件、成本、需要的选择、结果及次数限制。没有成本也应明确为无成本，不能把正文的第一项收益或损失含糊地当作发动费用。

已确认默认：只能在自己的时动阶段主动发动；随从与法术的每项主动能力默认每回合一次，明示次数覆盖默认。精确步骤引用[4.5](actions.md#主动能力)。

### 7.1.2 触发效果

在指定事件发生并符合条件时触发。必要内容：**事件是什么、观察谁、过滤条件、来源在哪些区域可用、结果、是否限次**。例如“此牌被抽到时”和“己方任意牌被抽到时”观察的对象不同。

“自动触发”不等于“从不需要选目标”。是否由玩家亲自选择依[操作窗口](actions.md#操作窗口)判断。若设计包含“你可以”，须进一步明确可放弃的步骤以及窗口外的自动处理；当前不为所有触发统一增加可拒绝发动的权限。

### 7.1.3 持续效果

在效果仍存在且生效条件成立时，持续影响指定范围。必要内容：**来源或承载者、存在期限、生效条件、受影响范围、提供的修正或规则**。

例如“此随从在战场期间，使附近友方随从攻击增加”必须再写清“附近”的具体范围、是否包含自身及增加数值。持续效果也可以赋予其他卡牌一项能力；这与持续修改攻击数值是不同结果。

### 7.1.4 替换与阻止效果

在一项变化尚未完成时，改写或阻止明确指定的部分。必要内容：**拟发生的事件、适用条件、改写哪个内容、改写结果、存在期限及使用限制**。例如改变购买目的地，或使某类伤害被阻止。

它与“发生后再做另一件事”不同：将购买目的地改为手牌，不等于购买进入弃牌堆后再返回手牌。能改写的事项必须明确；“无视护甲”只跳过护甲，不自动无视圣盾。替换如何排序、能否由玩家选用，由第八章规定。

## 7.2 每项效果的必要说明

**DES-002 设计稿应能独立回答以下问题。** 不适用的项目可以写“无”或引用已确认默认，不能留下会改变结果的空白。

| 项目 | 必须说明什么 |
| --- | --- |
| 工作方式 | 主动、触发、持续或替换／阻止；一段卡面有多项效果时分别描述。 |
| 来源与作用主体 | 谁拥有这项效果、谁承载它、谁获得收益或作出选择；赋予别人能力时尤其要区分。 |
| 可用区域与条件 | 在手牌、战场或其他明确区域中能否生效；建造、封锁等限制仍须满足。 |
| 时点或发动条件 | 主动发动在哪个阶段；触发观察什么事件；替换针对哪项尚未发生的变化。 |
| 对象与范围 | 玩家、卡牌或格子；区域、类型、控制关系、空间范围及是否包含自身。 |
| 选择与数量 | 全部、指定数量、至多数量、随机或玩家选择；必选／可选、是否允许重复及分配总量。 |
| 成本 | 资源、次数或明确要求的其他支付；哪些是成本、哪些是结果。复杂成本仍须先裁定。 |
| 结果 | 做什么、数值多少、按什么条件分支、先后或同批；具体变化引用第六章。 |
| 时间 | 何时执行、持续到何时、条件暂时不成立是否仅停止生效。 |
| 限次 | 上限、统计对象、统计期间，以及按尝试／成功发动／完成哪个事实计数。 |
| 中途失效 | 引用通用失败规则；若有例外，明确来源或目标变化后怎样处理。 |

这些是规则设计要素，不是程序字段清单。

## 7.3 触发事件目录

**DES-003 用具体事件代替含糊的“发动时”“受伤时”。** 下表整理现有文档和已讨论规则中的设计入口。精确发生点以对应行动或第八章为准，尚未裁定的入口不能只靠给它起名就视为可用。

### 7.3.1 卡牌与区域事件

| 可描述的时点 | 必须补充的条件与区别 |
| --- | --- |
| 从其他区域进入战场后 | [入场](../reference/keywords.md#入场)；说明观察自身还是其他牌。不能一概等同于玩家普通放置。 |
| 被抽到后 | 已因抽牌进入手牌；生成到手牌不是抽牌。 |
| 生成后 | 新的卡牌实例产生；不是既有牌转区。 |
| 进入弃牌堆后 | 说明是否要求特定原因；死亡、弃牌、法术清理不能仅因去向相同而混称。 |
| 被移除后 | 进入虚空；资源拾取后的本体消失不属于这个事件。 |
| 离开／进入指定区域后 | 指定来源、目的地和需要匹配的原因；两个描述不表示自动触发两次。 |
| 形态改变后 | 原实例变形；不自动产生入场。 |
| 被拾取／完成拾取时 | 区分观察资源牌还是拾取者，以及收益接受玩家；具体发生点待拾取时序裁定。 |

### 7.3.2 战斗与位置事件

| 可描述的时点 | 必须补充的条件与区别 |
| --- | --- |
| 移动到一个格子后 | 观察一次位置变化；普通移动逐格发生，瞬移只到终点。 |
| 进入某方领土后 | 原格不在、目标格进入；不同于“目前位于该领土”。 |
| 攻击声明后 | 已声明攻击，尚不代表命中或造成伤害。 |
| 攻击被取消时 | 不等同于造成 0 点伤害，也不自动满足攻击结算完成。 |
| 攻击结算完成后 | 不保证实际造成生命伤害；还须检查自己的触发条件。 |
| 造成／受到实际伤害后 | 区分观察伤害来源还是受击者；被完全抵挡的伤害依[6.1](lifecycle.md#伤害护甲与治疗)单独处理。 |
| 伤害被抵挡后 | 说明全部抵挡还是部分抵挡，以及限定圣盾、护甲还是其他原因。 |
| 实际治疗后 | 说明观察施加者还是被治疗者；实际回复量按第六章判断。 |
| 死亡时／击杀后 | 区分死亡者与击杀者；死亡确认、离场和效果执行的先后待第八章统一。 |

### 7.3.3 阶段、经济与效果事件

| 可描述的时点 | 必须补充的条件与区别 |
| --- | --- |
| 时停阶段开始／结束时 | 新的回合起始效果优先设计在时停开始；开始有本方窗口，结束没有。 |
| 你的／某玩家的时动阶段开始或结束时 | 必须写清所属玩家；每位玩家都有自己的时动阶段。 |
| 购买阶段开始／结束时、回合结束时 | 区分阶段与整回合；不得改变已确认的回合末手牌快照。 |
| 购买声明／成功／取消后 | 三个不同事实；购买成功不等于卡已进入手牌。 |
| 获得／支付星能后 | 指定变化方向、玩家、数值条件和原因，不能把任何余额变化都当作支付。 |
| 某效果成功发动后 | 区分成功发动与正文执行完成；受次数限制的计数口径须明确。 |
| 状态获得／失去后 | 指明状态及主体；首次获得和叠加现有状态是否同义须明确。 |

“即将受伤”“即将转区”“购买完成前”属于发生前的处理入口，通常用于替换、阻止或明示反制，不能与上表的发生后触发混为一种时点。哪些入口可用、是否允许选择，见[8.4](effects.md#结算前改写与结算后触发)。新设计不再泛用未区分前后的“当伤害发生时”。

## 7.4 对象、范围与选取方式

### 7.4.1 对象和区域

先确定对象是玩家、卡牌实例还是格子。卡牌条件可包括随从／法术／资源、所属区域、控制关系、职业、收集属性及当前状态；这些是不同筛选维度。

“非己方”可以包含无控制者对象；需要限定对方玩家控制的卡牌时应直接写出。攻击的合法目标仍受[4.4](actions.md#攻击与反击)限制，不能因为效果目录可以选择资源就让普通攻击也选择资源。

### 7.4.2 空间范围

设计可用下列范围表达自己的要求；超出现有条款的形状或定位方式须先补充规则：

- **自身、指定对象、指定格子**：明确跟随实例还是固定格子。
- **整个指定区域**：例如战场全部符合条件的随从，或自己的手牌。
- **距离 N 以内**：写清中心与距离算法，通常引用[2.5](elements.md#棋盘与空间关系)，并说明是否包含中心。
- **矩形区域**：写清宽、高、定位方式、方向及越界部分处理；“3×3”不能省略中心定义。
- **箭头或领土限定**：说明使用谁的有效箭头、哪一方领土，以及是当前位置条件还是进入事件。

持续影响范围与一次结算的目标范围分开：前者随条件变化重新判断，后者是否在选择时冻结、结算时复查，由第八章规定。

### 7.4.3 数量和选择

可用“全部符合条件者”“恰好 N 个”“至多 N 个”“随机 N 个”或明确的玩家选择。补充是否要求不同对象、可否为 0、点数如何分配、候选不足时怎么办。多个目标同时变化还是逐个处理，必须写清或引用通用批次规则。

窗口外的玩家选择已确认为系统从合法选项中随机选择。可选放弃是否纳入随机、组合选取的分布仍待裁定，不能默认系统替玩家寻找最大收益。

## 7.5 执行时间、存在期限与限次

### 7.5.1 执行时间

**现在处理、安排到明确的未来时点、重复若干次**是时间或执行次数的描述，不是与主动／触发并列的新种类。触发效果可以留下持续加成，主动能力也可以安排延迟结算。

延迟须写“哪位玩家的哪个阶段、开始还是结束、当前还是下一次”。慢速的准确落点未定，设计目录不自行补全。重复次数必须明确，不能把无限循环当作默认可执行设计。

### 7.5.2 存在期限与生效条件

可描述“本回合”“直到某个明确阶段结束”“承载者仍存在期间”“承载者在战场／指定区域期间”或其他明示期限。已有用法的精确边界见[8.6](effects.md#持续时间与失效)及区域转移规则；新组合仍需审阅。

**存在期限**决定效果是否还存在，**生效条件**决定存在的效果此刻是否提供作用。例如，一个随从在战场期间保有某光环，但只在己方领土内提供加成；走出领土可以使光环暂时不生效，不代表其定义被永久删除。

一次性赋予的修正不必跟随施加者离场而消失；它按自身期限和正逆向转区规则处理。想让修正持续更久，必须明确相应例外。

### 7.5.3 次数窗口与统计对象

已确认的主动能力默认是“这项能力每回合一次”。其他设计可明确提出每次入场、每个指定阶段、整局或指定回合里程碑等窗口，并同时说明上限与恢复边界；这些可选方案的具体细节需逐项确认，不能仅抄实现枚举。

还要说明次数属于这项能力、这张牌、被赋予的那份效果，还是玩家共享额度；按尝试、成功发动或完成结果中的哪一个事实消费。触发效果不自动套用主动能力的每回合一次默认。

## 7.6 结果与完整描述示例

结果可以是造成伤害、治疗、修改属性或星能、移动／转区、抽弃牌、生成、变形、添加或移除状态、赋予能力，以及明确的规则许可或限制。每项具体变化引用[第六章](lifecycle.md)和对应行动，不在这里重复定义生命周期。

**描述模板：** 在【来源区域／条件】下，于【发动或触发时点】，由【选择者】按【对象、范围、数量】确定目标，支付【成本】，执行【结果、数值、步骤】，维持到【期限】，受【次数窗口与计数口径】限制。持续效果则用“对哪些对象提供什么”替代主动选择与执行步骤。

**已有规则的展开例：**「保留」说明手牌在回合末弃置中的例外；它不自动赋予“每保留一回合增加伤害”。后者是一项需要另写增长数值、累计时点、适用伤害及累计记录保留方式的效果。这样设计者能分别检查效果文本与所需状态。
