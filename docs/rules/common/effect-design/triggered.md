触发效果观察一项明确事件，并在条件满足时引出后续效果。设计时必须分别写清**观察了谁的什么事件**与**之后对谁做什么**，不能用一句“触发后选目标”代替两者。本页是设计规格；记录、排序与执行时点见[第八章](../effects.md)。

## 7.3.1 必填要素

| 要素 | 含义与必填条件 | 选项或定义入口 | 省略时的处理 | 填写例 |
| --- | --- | --- | --- | --- |
| 来源与有效区域 | 必填。谁具有这项效果，在哪个区域能够观察事件。 | [对象字典](dictionary/targets.md)、[条件字典](dictionary/conditions.md) | 不默认为在所有区域都能触发。 | 具有此效果的随从在战场期间。 |
| 触发事件 | 必填。说明实际发生的事实及前后边界。 | [事件字典](dictionary/events.md) | “行动时”“受影响时”不够精确。 | 你的时动阶段开始时。 |
| 观察对象与过滤条件 | 必填。限定事件涉及的玩家或卡牌；额外过滤没有则写“无”。 | [对象](dictionary/targets.md)、[条件](dictionary/conditions.md) | 不能默认“任意事件”或“仅自身”。 | 阶段所属玩家是来源控制者；无其他条件。 |
| 发动方式 | 必填。符合条件必定引出效果，还是明确允许放弃。 | [选择字典](dictionary/selection.md) | 不因没写成本就自动得到可拒绝权限。 | 符合条件时必定触发，不可放弃。 |
| 结果接受者与作用范围 | 必填。与事件的观察对象分开写。 | [对象与范围](dictionary/targets.md) | 不默认观察对象就是结果目标。 | 获得收益的是来源控制者。 |
| 后续选择 | 必填；没有另选对象、模式或数量时写“无”。 | [选择字典](dictionary/selection.md) | 不能从“自动触发”推导“系统永远选目标”。 | 无选择，直接作用于来源控制者。 |
| 执行内容 | 必填。明确结果、数值、步骤及依赖。 | [结果字典](dictionary/results.md) | 不把事件的伤害量直接当作效果数值，除非明示引用。 | 该玩家获得 1 星能。 |
| 成本或附加支付 | 必填，无则写“无”；提出支付型触发时须说明是否允许拒绝和付不起怎么办。 | [成本字典](dictionary/costs.md) | 不凭空增加发动成本，也不自动批准支付型触发。 | 无。 |
| 触发限制 | 必填，明确无限次或限制内容。 | [次数字典](dictionary/usage.md) | 不套用主动能力的每回合一次。 | 每次符合条件均触发，无额外次数上限。 |
| 有限次数的统计与刷新 | 有限次时必填：归谁、何时消费、按哪个期间恢复。 | [次数字典](dictionary/usage.md) | “每回合一次”仍不足以回答触发被阻止后是否用掉。 | 该牌此效果的限制；计次边界须有对应裁定。 |

若正文留下加成或未来事项，继续填写[期限](dictionary/duration.md)；若授予另一项效果，链接那项效果的完整设计。引用事件数值时，要明确引用哪个事实及其量的定义，例如声明伤害与实际伤害不能混称。

## 7.3.2 三种对象与窗口

写“某个己方随从受伤后，选择另一个己方随从治疗”时，至少有三种身份：具有触发效果的**来源**、发生受伤事件的**被观察者**、后续治疗的**目标**。三者可以不同；过滤条件不能只写在最终目标一栏。

选择由谁亲自完成，按[4.1.1 操作窗口](../actions.md#操作窗口)判断。窗口外自动且默认合法随机，不因此取消这项效果。可选发动如何在窗口外转换、多个选择的随机分布等仍由[8.2](../effects.md#目标模式与数量选择)统一裁定；不能把“你可以”作为无须说明的通用选项。

若观察[死亡](../lifecycle.md#死亡与消灭)，使用该事件的定义与已确认顺序：清理本体后再结算死亡效果，不能另加“执行时本体仍在战场”的条件使死亡效果永远失效。若需要死亡位置，引用死亡事件保留的位置。**将牌移入弃牌堆和献祭不等于死亡**；要观察它们，应选择各自的事件与原因。

## 7.3.3 可复制填写模板

```text
效果名称：
工作方式：触发
来源与有效区域：
触发事件：
事件观察对象：
事件过滤条件：无／逐项说明
发动方式：必定触发／待裁定的可选方式及其完整处理
结果接受者与范围：
后续选择：无／选择者、候选、方式、数量、是否允许放弃
成本：无／明确支付规格及付不起的处理
执行内容：操作、数值、步骤；引用事件数据时注明数据含义
触发限制：无额外上限／上限、统计对象、期间
有限次的消费与刷新：不适用／引用条款或审阅问题
持续与延迟：无／完整期限与未来时点
其他例外：无／明确改写部分
依赖的未决裁定：无／具体问题与链接
卡面文案：
```

## 7.3.4 完整示例：时动供能

**教学设计示例，不新增正式卡牌。** 本例使用己方阶段事件，避免将所有起始收益写成回合开始。

| 要素 | 本例填写 |
| --- | --- |
| 来源与区域 | 一张具有本效果、位于战场且效果有效的随从。 |
| 事件及观察对象 | 一名玩家的时动阶段开始；只匹配来源控制者的时动阶段。 |
| 额外过滤 | 无；不要求该随从受伤或位于某片领土。 |
| 发动方式 | 每次匹配事件均触发，不允许放弃。 |
| 结果接受者 | 来源控制者，不指定任何随从为目标。 |
| 后续选择与成本 | 均无。 |
| 执行内容 | 结果接受玩家获得 1 星能；一个结果步骤。 |
| 次数限制 | 无额外触发上限。不是主动能力，不引用每回合一次默认。 |
| 计次与刷新 | 没有独立使用额度，不适用。 |
| 持续、延迟与例外 | 均无；这项收益不是需要来源持续提供的光环。 |
| 未决依赖 | 与其他阶段开始效果的排序、等待期间来源变化，统一依 8.5 与 8.7，不由本例规定。 |

**卡面文案：**「你的时动阶段开始时，获得 1 星能。」设计稿写明来源在战场生效，卡面短文案不能被另行解释为手牌中也会触发。

在无其他相关效果和控制变化的局面中，A 控制该随从，A 的时动开始后获得 1 星能；B 的时动开始不匹配本例条件。若经已定义的其他效果获得额外时动阶段，每次该阶段开始都重新匹配，本例没有暗含每回合一次。

## 7.3.5 含糊写法与修正

**含糊：**「时动开始时获得星能。」无法判断是每位玩家的时动、自己的时动，谁获得以及获得多少。

**修正：** 用上例明确观察“来源控制者的时动阶段开始”、收益接受者与数值。若想限制每回合只获一次，必须另外写入次数规格，并解决其计次边界，不能认为阶段名天然提供这一限制。

另一个常见错误是把“死亡后”改写成“进入弃牌堆后”。这样会错误地包含其他离场原因；原意为死亡就应保留死亡事件，而不是用目的区域近似。

## 7.3.6 交付前检查

- 事件、来源、被观察者和结果目标能否分别指出？
- 前置条件是事件的过滤条件，还是执行时须再判断的分支？二者是否写清？
- 是否把尚待裁定的可选发动、事件入口或来源失效处理写成了默认？
- 有无选择、是否限次、是否留下持续作用，都是否明确填答？
