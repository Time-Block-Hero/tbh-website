触发效果是[持续效果](continuous.md)提供的一种作用：在这项作用有效期间，匹配指定事件并执行相应内容。事件既可以是“放置完成”，也可以是“攻击即将发生”；不能把所有触发都定义成已经发生的事实之后。

**触发时点与正文速度分开。** 独立时停期间，普通卡牌触发默认慢速，包括入场、移除、被保留和进度完成等；显式快速的正文才当场执行。发生前响应必须在变化发生前处理，替换及持续贡献也不属于普通慢速正文，统一见[3.3.2](../rounds.md#待结算效果的登记与顺序)。准备玩家选择与正文结算分别遵守[8.2.1](../effects.md#选择时点与操作窗口)，不能从“移除时”等事件用语推断为快速。

已经触发后，来源死亡或离场不会自动取消该次结算，统一见[8.7.2](../effects.md#来源离场封锁与控制权变化)。持续效果是否还能提供下一次触发，与已经产生的这一次是否继续结算，分别判断。

## 7.4.1.1 必填要素

先在外层持续效果写好存在期限、生效条件和作用范围，再填写这一项触发：

| 维度 | 需要写清什么 | 例子 |
| --- | --- | --- |
| 触发事件 | 具体事件及发生前／后含义。 | 自身被放置；敌方随从即将攻击。 |
| 事件主体 | 事件中的哪一个对象与具有触发能力的对象对应。 | 自身被放置，或其他对象成为攻击发起者。 |
| 监听范围与玩家角色 | 监听自身、友方、对方或更广的事件；按哪个玩家角色判断关系。 | 只监听敌方发动的攻击；不能把攻击者和受击者的关系混写。 |
| 事件筛选 | 在事件类别与监听范围之外，再满足哪些要求。 | 攻击来源必须是随从；不是所有行动都匹配。 |
| 执行内容 | 匹配后做什么，引用哪个事件对象、数值或新选择。 | 获得星能；取消本次攻击。 |

触发执行中的选择按[7.5](execution.md)描述。它不等于允许玩家决定是否发动整项触发；新增“可以选择不触发”的设计须另行明确规则，不能作为普通触发的默认开关。

## 7.4.1.2 三种对象与窗口

设计时分别指出：

- **获得作用的对象：** 外层持续效果把触发提供给谁。
- **事件关联对象：** 谁放置、攻击、受伤，或处于哪个阶段；由事件与监听条件确定。
- **执行目标：** 最终获得星能、受到伤害、被移动或被选择的对象。

「星能石」由自身获得入场触发，监听自身从其他区域进入战场，执行内容为对应玩家获得 1 星能。这三个角色并不要求是同一个对象。

有触发不代表有玩家操作窗口。若主体需要玩家选择，按[4.1.1 操作窗口](../actions.md#操作窗口)：非本人操作窗口由系统自动选择，无专门规定时从合法选项中随机选取。触发条件不能借此开放额外主动行动。

## 7.4.1.3 限次与生效条件

「天元防壁」每回合最多三次无效敌方随从攻击。其组织方式是：外层持续效果以“本回合这项触发已成功发动的次数少于三次”为生效条件；内层监听敌方随从的攻击前事件，再执行无效本次攻击。

因此，限次可以由外层条件表达，不必给每项触发再复制一套主动能力的次数字段。统计谁、统计哪种事实及期间必须明确；攻击已取消时其他防壁不继续消耗次数，见[4.4.1](../actions.md#攻击步骤)。通用计次参数见[次数字典](dictionary/usage.md)。

## 7.4.1.4 可复制填写模板

```text
所属持续效果：引用其期限、生效条件、作用范围
触发事件：事件名称，以及发生前／后
事件主体：与本项作用持有者有关的对象角色
监听范围与玩家角色：自身／友方／对方等，明确关系参照
附加事件筛选：无／逐项说明
执行内容：步骤、对象、数值及需要的选择
次数条件：无额外限制／由所属持续效果的生效条件引用
引用规则与明示例外：具体问题及主定义链接
卡面文案：
```

## 7.4.1.5 实牌示例：星能石

持续效果随该牌存在，向自身提供入场触发，没有额外生效条件；触发匹配该牌从其他区域进入战场（包括放置），主体令相应玩家获得 1 星能。其主动部分为空：玩家选择放置卡牌，并不等于另行声明发动一项主动能力。

入场作为关键词的通用范围见[入场](../../reference/keywords.md#入场)。放置入场与拾取同时相关时，按已确认的[先入场、后拾取](../actions.md#放置与拾取)；本例不另定来源离场、目标选择或嵌套触发顺序。

## 7.4.1.6 进度效果

**进度效果是触发效果的一个特例。** 它在满足计数条件时先累计状态，在达到目标时才触发执行内容。组织上仍由持续效果提供这一项触发作用，不另增加与主动或持续效果平级的种类。状态变化和完成规则的唯一主定义见[6.2.6 进度](../lifecycle.md#进度)。

设计一项进度效果，除普通触发所需的来源、关系和执行内容外，还需填写：

| 要素 | 必须交代的内容 | 现有设计例子 |
| --- | --- | --- |
| 计数条件与增加量 | 统计什么事实、哪个对象或玩家；每次按次数、牌数、资源量还是格数增加。 | 训练服务机群累计抽牌张数；炮台巡游者累计自身移动格数。 |
| 目标值 | 完成一次需要多少进度；改变目标的效果另明确计算与适用范围。 | 星光运输管线的目标为 4 点星能。 |
| 完成方式 | 循环或一次性；引用 6.2.6 的扣除／标记规则。 | 循环收益与完成后停止的一次性任务。 |
| 有效区域与状态保留 | 何时计数，何时停止；回合切换、离场、变形后如何处理当前值。 | 普通当前进度按 6.2.6 在逆向转区归零；特殊保留例外须明示。默认在场且有效时计数；变身延续同项记录，新项从 0 开始，详见 6.2.6。 |
| 完成效果 | 达标后执行什么，选择哪些对象；保留普通触发的合法性与窗口约束。 | 获得星能、抽牌、造成伤害或改变形态。 |

「天庭乐师」统计效果发动／触发次数时，其他牌仅增加进度不算一次效果触发；完成进度产生的效果才属于触发。天庭乐师计入自己的完成效果；取消结果仍按所观察的具体事件判断，主定义见 6.2.6。

「借时蜉蝣」和「集群主脑-埃米莉丝」可以由外部直接触发指定进度效果；这与推进进度不同，具体状态处理引用 6.2.6。集群主脑选择三个不同的有效进度效果，不足取全部；借时蜉蝣有多个候选时由玩家选一，窗口外合法随机。已完成一次性任务可以被外部触发奖励，状态处理见 6.2.6。

### 7.4.1.6.1 进度卡文格式

采用统一写法：

```text
[循环进度：目标值] 计数：统计对象与单位。完成：完成效果。
[一次性进度：目标值] 计数：统计对象与单位。完成：完成效果。
```

“计数”描述每次事实带来的增加量，按张数、格数、资源量或发生次数累计；它不是每次都发动一项效果。“完成”才是达到目标后触发的执行内容。余量、即时扣除及逆向重置等通则引用第六章，不在每张牌重复展开；特殊保留方式必须另写例外。

例如「星光运输管线」：`[循环进度：4] 计数：你获得的星能数量。完成：抽一张牌并令其本回合获得保留。`

「迷离之剑-烬白」的入场生成资源与一次性拾取进度分别描述；变身后另一形态具有自己的循环移动进度。同一项进度延续记录，新项从 0 开始，见[6.2.6](../lifecycle.md#进度)；形态与其他状态继承见[6.6.2](../lifecycle.md#升级变形与复制)。
