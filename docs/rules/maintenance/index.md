## 逐章起草与审阅流程

默认每次起草一章；用户明确要求批量起草时，按指定章节一起交付审阅。本次范围为第一章修订及第二至第四章草案。起草时：先依据两版旧规则书提炼完整草案，再交给用户检查和提出修改意见。对文档中的自相矛盾、含糊或缺失之处，按需只读核对 unified 当前引用的实现，分别说明旧文档的说法、实际处理方式和拟议条款。实现用来解释现状，不能自动替代玩法决定。

用户通过问答或批注修改草案；本次指定章节交付后等待集中审阅，再推进后续章节。未确认正文保持草稿，来源、歧义和待决定事项另行记录，正式正文不写成聊天记录或程序说明。

旧文档的“正式”标题、现有程序行为或示例都不能代替用户对新规则的确认。未裁定内容保持草稿。

## 唯一性与可复盘性

同一规则只维护一个正式定义。流程页说明时间顺序，行动页说明操作步骤，状态章节说明结果变化，时序章节说明多项效果如何组合，关键词库说明词条专属语义。其他位置使用链接。

给定相同初始局面、玩家选择和随机结果，正文应足以唯一推演整局。用完整案例检查选择、支付、触发、失败、检查与行动结束的遗漏。

## 未来模式

未来 Rogue 或剧情模式实际开始设计时再新增模式章节。沿用通用的星能运营、卡组成长、棋盘对弈、回合流程和商店购买，明确记录该模式的补充与例外。
