## 逐章起草与审阅流程

默认每次起草一章；用户明确要求批量起草时，按指定章节一起交付审阅。第一至第八章及启用关键词的本轮审阅已结束；剩余缺省参数按授权固定，不重复询问。标准模式第九至第十一章按本次批量授权补全草案，待决定配置集中记录，不重开通用条款。先承接用户已确认的黄金准则，再以旧规则书和开发文档补足草案。对资料中的自相矛盾、含糊或缺失之处，按需只读核对 unified 当前引用的实现，分别记录历史设计、实际行为和拟议条款。实现用来解释现状，不能自动替代玩法决定。

本轮用户已明确终止分批审阅。明确裁定优先，授权补全记录其依据，未完成的维拉／烬白设计排除本轮实机测试。后续根据试玩问题修订，不将这些固定细节再次列为待答。页面保留草稿发布状态，直到整部规则书完成正式发布；这不使已固定试玩正文失效。

旧文档的“正式”标题、现有程序行为或示例都不能代替用户对新规则的确认。未裁定内容保持草稿。

## 唯一性与可复盘性

同一规则只维护一个正式定义。流程页说明时间顺序，行动页说明操作步骤，状态章节说明结果变化，时序章节说明多项效果如何组合，关键词库说明词条专属语义。其他位置使用链接。

给定相同初始局面、玩家选择和随机结果，正文应足以唯一推演整局。用完整案例检查选择、支付、触发、失败、检查与行动结束的遗漏。
