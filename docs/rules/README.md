## 已确认的目录与范围

- `start/`：规则 Wiki 导读。
- `common/`：通用游戏规则，第一至第八章。回合流程、星能、商店购买和卡组成长均为所有模式共享的核心。
- `standard/`：标准对战，第九至第十一章。1v1 胜负、构筑与开局配置，以及资源生成等对局自动逻辑。
- `reference/`：关键词库与裁定，第十二至第十三章。关键词提供统一查询入口；详细机制已有主章节时，词条链接主定义，例如建造的定义在 4.2.3。
- `maintenance/`：待裁定问题、版本与变更记录、来源与确认记录。

本版取消高度维度；资源共存、拾取资格及离场核心已确认，剩余交互以审阅记录为准。全局资源生成方案不归入棋子状态变化章。未来实际设计新模式时，再新增模式章节。

规则使用游戏语言，不写程序类型和架构；给定初始局面、玩家选择与随机结果，应能唯一推演整局。章节与小节采用 2、2.1、2.2.1 等编号，便于讨论引用；编号不属于稳定 ID。

## 文件约定

- 每页 frontmatter 必须有 `title`、稳定 `id` 和 `status`（`draft`／`approved`／`retired`）。未经确认保持 `draft`。
- `navigation.json` 控制分组与页序；分组使用 `pages`，页面使用 `children` 嵌套子页，按深度优先顺序阅读。章节索引和子页都必须列出。稳定 ID 不包含目录序号，移动文件时保留 ID。构建同时生成扁平页索引、树状目录和父页面关系，供搜索、面包屑和侧栏使用。搜索匹配页名、页面 ID、章节标题及字典条目；词条还可以按简述与参数搜索，结果直达锚点。
- 使用普通 Markdown（标题、表格、列表、代码块）和相对 `.md` 链接。链接可带标题生成的锚点。构建器会检查目标页面与锚点。
- 每个正式章节的二级及更深标题必须带分级编号。标题锚点先忽略开头的阅读编号，再保留字母、数字、中文与连字符；空格改为连字符，重复标题追加 `-2`、`-3`。长期条款引用应在标题中包含稳定规则编号。拆页时更新站内链接，并在 `redirects.json` 保留旧深链接到新页面／锚点的映射；构建会校验目标。
- 站内 URL 为 `wiki.html#/effects`；节内 URL 为 `wiki.html#/keywords@入场`。页面 ID 保持稳定，修改已被引用的标题前检查链接。
- 原始 HTML 仅作为文字显示，不执行。外部链接支持 HTTPS／HTTP；不支持脚本 URL。正文不嵌入交互组件。四列及以上表格由渲染器提供可键盘聚焦的横向滚动容器，窄屏无需将字段挤成单字列。
- 图片使用从当前页面到根目录 `assets` 的 `../../../assets/...` 路径。棋盘等空间插图可以使用本地 SVG，点击可打开原图。流程和状态迁移统一写成 Markdown 的 `mermaid` 围栏代码块，使用 `flowchart`；不再手工维护对应 SVG。Wiki 使用固定版本的本地 Mermaid Tiny 渲染，图下可展开源码；失败时保留可读源码。图示须附文字说明范围及未定边界。
- 第七章入口为 `common/card-effects.md`；设计说明在 `common/effect-design/`，八类字典在其 `dictionary/` 目录。主动能力独立；持续效果提供触发、替换、属性、数值、移动、放置六类作用，触发和替换在导航中隶属于作用页。执行内容单独说明，第八章决定结算时序；不得把重构提案当作现行组织方式。
- 字典一行一词条：第一列可写 `**词条** {#稳定锚点}`，锚点为中文、字母、数字或连字符。生成器提供词条链接、行定位及独立搜索索引，不加入本页目录；条目锚点同样参与站内链接和重定向校验。不要用可见 HTML 手写锚点。
- 复杂说明采用 Markdown 引用块：首行 `> [!DETAILS] 说明标题`，随后 `>` 空行及带 `>` 的正文。页面渲染为默认收起的原生折叠，内部 Markdown 仍通过安全渲染和链接校验；主要定义、参数和例子保留在表格中。
- 单一主题只维护一个正式定义，归属见[规则主定义索引](maintenance/index.md#规则主定义索引)，其他页链接它；暂不支持跨页内容嵌入。关键词使用精确词条锚点，例如 `[入场](../reference/keywords.md#入场)`。

## 构建与检查

```sh
npm ci --ignore-scripts
npm run build:wiki
npm run test:wiki
```

将 Markdown、导航和生成的根目录 `wiki-data.js` 一起提交。后者不是编辑源；它让现有静态站和直接打开 HTML 的预览都能阅读 Wiki，不必启动额外框架。首次安装依赖之后，构建与测试均不需要网络。
