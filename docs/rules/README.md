# 规则 Wiki 编写交接

这里是规则 Wiki 的 Markdown 源码。五组导航、十二章的目录与范围已获用户确认；所有页面仍为 `draft`，正文按章起草、审阅与确认。目录标题与提纲不构成已确认玩法。不要自动复制旧 Rulebook 或按当前代码补写规则。

## 已确认的目录与范围

- `start/`：规则 Wiki 导读。
- `common/`：通用游戏规则，第一至第七章。回合流程、星能、商店购买和卡组成长均为所有模式共享的核心。
- `standard/`：标准对战，第八至第十章。1v1 胜负、构筑与开局配置，以及资源生成等对局自动逻辑。
- `reference/`：关键词库与裁定，第十一至第十二章。关键词只在词条定义，正文通过链接引用。
- `maintenance/`：待裁定问题、版本与变更记录、来源与确认记录。

本版取消高度维度；占格、飞行、拾取物的替代细节仍待裁定。全局资源生成方案不归入棋子状态变化章。未来实际设计新模式时，再新增模式章节。

规则使用游戏语言，不写程序类型和架构；给定初始局面、玩家选择与随机结果，应能唯一推演整局。页面标题中的章节号用于阅读顺序，不属于稳定 ID。

## 下一次讨论

先依据旧规则书完成一章草案，再交给用户审阅。仅在矛盾、含糊或缺失处按需只读核对 unified 当前引用的实现，明确区分文档、程序现状和拟议规则。用户通过问答或批注修改；确认本章后再继续下一章。未确认的正文保持 `draft`，记录来源和替代关系；程序说明与规则正文分开。

## 文件约定

- 每页 frontmatter 必须有 `title`、稳定 `id` 和 `status`（`draft`／`approved`／`retired`）。未经确认保持 `draft`。
- `navigation.json` 控制分组与页序；章节索引和子页都必须列出。稳定 ID 不包含目录序号，移动文件时保留 ID。
- 使用普通 Markdown（标题、表格、列表、代码块）和相对 `.md` 链接。链接可带标题生成的锚点。构建器会检查目标页面与锚点。
- 标题锚点保留字母、数字、中文与连字符；空格改为连字符，重复标题追加 `-2`、`-3`。长期条款引用应在标题中包含稳定规则编号。
- 站内 URL 为 `wiki.html#/effects`；节内 URL 为 `wiki.html#/keywords@入场`。页面 ID 保持稳定，修改已被引用的标题前检查链接。
- 原始 HTML 仅作为文字显示，不执行。外部链接支持 HTTPS／HTTP；不支持脚本 URL。正文不嵌入交互组件。
- 图片使用从当前页面到根目录 `assets` 的 `../../../assets/...` 路径。本轮不需要正文图片。
- 单一主题只维护一个正式定义，其他页链接它；暂不支持跨页内容嵌入。关键词使用精确词条锚点，例如 `[入场](../reference/keywords.md#入场)`。

## 构建与检查

```sh
npm ci --ignore-scripts
npm run build:wiki
npm run test:wiki
```

将 Markdown、导航和生成的根目录 `wiki-data.js` 一起提交。后者不是编辑源；它让现有静态站和直接打开 HTML 的预览都能阅读 Wiki，不必启动额外框架。首次安装依赖之后，构建与测试均不需要网络。
